# Импорт исторических таблиц и событий

Парсер читает оригинальный файл и сохраняет его в raw-архив. Номер столбца и строки в схемах начинается с нуля. Неизвестный текст в числовой ячейке вызывает ошибку; пустые ячейки и стандартные обозначения отсутствия данных не становятся нулями.

## Росстат

Исторический ИПЦ находится на [странице цен](https://www.rosstat.gov.ru/statistics/price/): «Индексы потребительских цен … месяцы (с 1991 г.)». В проверенном файле общий индекс — лист `01`, раздел «к концу предыдущего месяца». Годовая строка «к декабрю предыдущего года» не смешивается с месячным декабрём. Это учтено в схеме. При изменении структуры нужно проверить название листа и базу сравнения; неоднозначность вызывает ошибку.

```sh
uv run usd-rub import-table --input /путь/к/ИПЦ.xlsx --spec config/imports/rosstat_cpi.json
```

Парсер `month_matrix` понимает годы в столбцах и названия месяцев в строках. Для другой структуры нужно выбрать `row_timeseries`, `long` или `period_rows`. Схему следует проверить по реальному файлу.

Оборот розничной торговли — [официальный раздел](https://rosstat.gov.ru/statistics/roznichnayatorgovlya). `config/imports/retail_long.json` — шаблон для двух столбцов: дата и оборот в млрд рублей. Если файл содержит индекс физического объёма, нельзя сохранять его под единицей `RUB bn`: нужен отдельный ряд и явная единица.

## Минфин, Urals и другие месячные ряды

`minfin_oil_gas_long.json` — шаблон для месячных нефтегазовых доходов; `minfin_oil_gas_ytd.json` — для накопленных сумм с начала года. Загрузчик `minfin_oil_gas` находит документ «Краткая ежемесячная информация» на [странице бюджета](https://minfin.gov.ru/ru/statistics/fedbud/), затем XLSX. Распознаются строка показателя, колонка названия, даты, единица «млрд руб.» и накопленная база. В проверенном файле история начинается в 2011 году. Сохраняются исходный `oil_gas_revenue_ytd` и месячный `oil_gas_revenue`.

Даты вида `янв.23 ***` распознаются, исходная подпись со сноской сохраняется в `source_period_label`. Сноски нельзя просто удалить вместе с данными: это потеряло бы часть последних месяцев.

```sh
uv run usd-rub import-table --input /путь/к/доходам.xlsx --spec config/imports/minfin_oil_gas_ytd.json
```

Преобразование `ytd_to_monthly` вычитает предыдущий месяц внутри года. Январь сохраняется как есть. Если предыдущий месяц отсутствует, месячная сумма не вычисляется: разность через пропущенные месяцы была бы ошибкой. Значения разных лет не вычитаются друг из друга.

Шаблон `urals_long.json` предназначен для подтверждённых официальных месячных цен Urals. Загрузчик `economy_urals` получает доступный официальный архив с мая 2024 года; полной десятилетней истории пока нет. Дневные оценки Argus не используются. Аналогично можно импортировать CPI РФ, промышленное производство, ФНБ, платёжный баланс и другие табличные ряды, задав их собственные имена и единицы.

Для столбцов с датами в первой строке и названием ряда в первом столбце:

```json
{
  "parser": "row_timeseries",
  "sheet": "Лист1",
  "row_pattern": "Нефтегазовые доходы",
  "name": "oil_gas_revenue",
  "unit": "RUB bn",
  "date_row": 0,
  "label_column": 0
}
```

Для строк с отдельным годом и последующими названиями месяцев используется `period_rows`; поля схемы: `columns`, `sheet`, `label_column`. `columns` задаётся как в `long`. Для колонок с датой можно указать `date_format`; для масштаба значения — `scale`, например 0.001 при переводе миллионов в миллиарды.

Ссылки на вложения можно найти без загрузки всех файлов:

```sh
uv run usd-rub discover-tables --url https://www.cbr.ru/statistics/macro_itm/external_sector/etg/ --pattern 'Внешняя торговля'
```

## Фьючерсы MOEX

```sh
uv run usd-rub moex --spec config/moex_futures.example.json --start 2026-01-01 --end 2026-11-17
```

Это пример для одного контракта SiZ6, а не склеенный десяти­летний фьючерс. Для другого контракта меняются `path` и имена рядов. Для Si цена задана в рублях за 1000 USD. В запросе указан конкретный режим торгов, чтобы не смешивать строки с разных досок. Отсутствующее поле вызывает ошибку, `null` не становится нулём. Загрузчик `moex_si_front` отдельно строит ближайший контракт за 2015–2026: переход после даты «последний день торгов минус 5 календарных дней», без корректировки старых цен. Цена переведена в RUB/USD; контракт и экспирация сохранены в каждой строке.

## События и документы

Для налоговых сроков, объявленных валютных операций, санкционных и правовых изменений используется CSV со столбцами:

```text
event_id,event_type,event_time,publication_time,effective_time,source_url,value,unit,evidence
```

Все три времени должны содержать часовой пояс. `evidence` — подтверждающий фрагмент документа. `event_id` уникален. Это схема импорта проверенных событий, автоматическая юридическая интерпретация не выполняется.

```sh
uv run usd-rub import-table --input /путь/к/events.csv --spec config/imports/events.json
uv run usd-rub extract-document --input https://www.cbr.ru/Collection/Collection/File/62428/Bbs2609r.pdf --output data/documents/bulletin.json
```

`extract-document` сохраняет текст HTML/PDF со ссылкой, SHA256 и номерами страниц. Можно обработать архивные обзоры ЦБ о продажах экспортёров, релизы Минфина и официальные санкционные документы; числовые факты требуют проверки по документу. Сканированные PDF без текстового слоя требуют OCR, который здесь не включён.

Архив OFAC загружается с текстами решений:

```sh
uv run usd-rub ofac --start 2015-01-01 --end 2026-11-18 --documents --output data/documents/ofac_2015_2026.json
uv run usd-rub cbr-releases --start 2015-01-01 --end 2026-11-18
uv run usd-rub sanctions
```

OFAC сохраняет дату, заголовок, ссылку и текст решения. Точная внутридневная публикация и дата вступления санкции в силу не выдумываются. Текущие списки санкций хранятся в `data/entities`, отдельно от исторических документов.

GDELT отключён по требованию пользователя. Сохранённые ранее пробные файлы не используются при сборке признаков.

При следующем запуске `features` импортированные CSV событий учитываются по `publication_time`. Для каждого типа создаётся сумма значений в день действия и расстояние до ближайшего уже объявленного события. Для налогового календаря используйте `event_type=tax_payment_day`, `value=1`, `unit=event`. Эти признаки не моделируют длительность действия правового режима.
